# Contributing

Open a pull request against `master`. The developer notes in the README cover Docker builds and releases.

For documentation and user-facing text, follow the [writing principles](https://github.com/ratschlab/writing-rules/blob/1e2060df768d8aa2e7c88f65f48217b8b409a234/guides/PRINCIPLES.md) and run the [text check](docs/writing/README.md). Verify factual claims, defaults and examples against the implementation.

For pull requests, reviews and commit messages, see the [engineering communication guide](https://github.com/ratschlab/writing-rules/blob/1e2060df768d8aa2e7c88f65f48217b8b409a234/guides/ENGINEERING.md).

Before proposing a new feature, option, flag, endpoint or API field, check it against the [stewardship principles](https://github.com/ratschlab/writing-rules/blob/1e2060df768d8aa2e7c88f65f48217b8b409a234/guides/STEWARDSHIP.md).

If an LLM agent wrote code for your change, run the checklist in the [guide to LLM-written code](https://github.com/ratschlab/writing-rules/blob/1e2060df768d8aa2e7c88f65f48217b8b409a234/guides/LLM_CODE.md) before opening the pull request.
